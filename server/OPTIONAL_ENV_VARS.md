# 环境变量可选配置说明

**更新日期**: 2026-04-14  
**状态**: ✅ 已完成

---

## 变更概述

根据用户需求，将 `ENCRYPTION_KEY` 和 `JWT_SECRET` 从**强制必需**改为**开发环境可选**。

---

## 行为说明

### 开发环境 (NODE_ENV !== 'production')

**不设置密钥时**:
- ✅ 服务可以正常启动
- ⚠️  显示警告信息，提示使用默认密钥
- ⚠️  提醒生产环境必须设置自定义密钥
- 🔐 使用内置的默认密钥（仅用于开发测试）

**设置密钥时**:
- ✅ 使用自定义密钥
- ✅ 显示"密钥已配置"确认信息
- 🔒 更安全，推荐使用

### 生产环境 (NODE_ENV === 'production')

**不设置密钥时**:
- ❌ 服务拒绝启动
- ❌ 显示详细的错误信息
- 💡 提供密钥生成命令

**设置密钥时**:
- ✅ 正常启动
- ✅ 使用自定义密钥

## 启动示例

### 开发环境 - 不设置密钥

```bash
npm run dev:all
```

**输出**:
```
⚠️  警告: 未设置 ENCRYPTION_KEY，使用默认密钥（仅用于开发）
⚠️  生产环境请务必设置自定义加密密钥！
⚠️  使用默认加密密钥（开发模式）

⚠️  警告: 未设置 JWT_SECRET，使用默认密钥（仅用于开发）
⚠️  生产环境请务必设置自定义JWT密钥！
⚠️  使用默认 JWT 密钥（开发模式）

🔒 CORS 允许的来源: [...]
📦 存储模式: JSON
✅ 服务器启动成功！
```

### 开发环境 - 设置密钥

```bash
# 在 .env 文件中设置
ENCRYPTION_KEY=my-custom-encryption-key-32-chars-long
JWT_SECRET=my-custom-jwt-secret-32-chars-long

npm run dev:all
```

**输出**:
```
✅ 加密密钥已配置
✅ JWT 密钥已配置
🔒 CORS 允许的来源: [...]
📦 存储模式: JSON
✅ 服务器启动成功！
```

### 生产环境 - 不设置密钥

```bash
NODE_ENV=production npm run start
```

**输出**:
```
============================================================
❌ 生产环境未设置加密密钥！
============================================================
请在 .env 文件中设置 ENCRYPTION_KEY 环境变量

生成密钥命令:
  openssl rand -base64 32

或者:
  node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"

示例:
  ENCRYPTION_KEY=your-32-character-or-longer-encryption-key-here
============================================================

[服务退出]
```

## 安全建议

### 开发环境

1. **快速开始**: 可以不设置密钥，直接启动服务
2. **团队协作**: 建议在 `.env.example` 中提供示例密钥
3. **本地测试**: 使用默认密钥不影响功能测试

### 生产环境

1. **必须设置**: 生产环境强制要求设置自定义密钥
2. **密钥强度**: 至少32字符，建议使用随机生成
3. **密钥管理**: 
   - 不要提交到版本控制
   - 定期轮换密钥
   - 使用环境变量或密钥管理服务

## 生成强密钥

### 方法1: 使用 OpenSSL
```bash
openssl rand -base64 32
```

### 方法2: 使用 Node.js
```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

### 方法3: 使用 PowerShell
```powershell
[Convert]::ToBase64String((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 }))
```

## 常见问题

### Q: 为什么开发环境可以不设置密钥？
A: 为了方便快速开发和测试，避免每次都要配置环境变量。但生产环境仍然强制要求设置。

### Q: 默认密钥安全吗？
A: 默认密钥仅用于开发测试，**不安全**。生产环境必须使用自定义密钥。

### Q: 如何判断当前是开发还是生产环境？
A: 通过 `NODE_ENV` 环境变量判断。未设置或设置为 `development` 时为开发环境。

### Q: 可以在生产环境使用默认密钥吗？
A: **绝对不可以**！生产环境会检测并拒绝启动。

## 迁移指南

### 从旧版本升级

如果你之前已经设置了密钥，**无需任何改动**，服务会继续使用你的自定义密钥。

如果你之前没有设置密钥（旧版本会启动失败），现在可以：
1. **开发环境**: 直接启动，使用默认密钥
2. **生产环境**: 必须设置密钥才能启动
