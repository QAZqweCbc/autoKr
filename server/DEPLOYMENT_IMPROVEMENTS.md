# 🚀 部署系统改进总结

## 新增文件清单

### 1. 自动化脚本（4个）

#### check-environment.sh
- **功能**: 部署前环境检查
- **检查项**: 
  - 操作系统版本
  - Node.js 18+ 版本检查
  - npm、Git、MySQL、Redis等工具
  - PM2、Nginx等服务
  - 端口占用（3000、2233）
  - 磁盘空间（至少10GB）
  - 内存（至少2GB）
  - Playwright系统依赖库
- **输出**: 彩色报告，显示通过/警告/失败统计

#### deploy.sh
- **功能**: 首次部署自动化
- **流程**:
  1. 检查root用户（不建议使用）
  2. 检测操作系统
  3. 检查Node.js和MySQL环境
  4. 安装所有依赖（包括Playwright）
  5. 配置环境变量（自动生成安全密钥）
  6. 编译前后端项目
  7. 初始化数据库和管理员账号
  8. 安装和配置PM2
  9. 启动服务并设置开机自启
  10. 显示部署状态和访问信息
- **特点**: 
  - 彩色输出
  - 交互式确认
  - 错误处理
  - 自动生成JWT_SECRET和MAIN_API_KEY

#### update.sh
- **功能**: 安全更新生产环境
- **流程**:
  1. 检查Git仓库
  2. 备份当前版本（代码、.env、数据库）
  3. 拉取最新代码
  4. 智能更新依赖（仅当package.json变化）
  5. 重新编译项目
  6. 执行数据库迁移（可选）
  7. 重启服务（PM2或systemd）
  8. 健康检查（主服务和认证服务）
  9. 清理旧备份（保留7天）
- **特点**:
  - 自动备份
  - Git stash支持
  - 智能依赖更新
  - 健康检查
  - 失败时提示回滚

#### rollback.sh
- **功能**: 快速回滚到上一个版本
- **流程**:
  1. 检查备份目录
  2. 显示备份信息
  3. 回滚代码到上一个提交
  4. 恢复.env文件
  5. 恢复数据库（可选）
  6. 重新安装依赖
  7. 重新编译项目
  8. 重启服务
  9. 健康检查
- **特点**:
  - 显示备份列表
  - 交互式确认
  - 数据库恢复可选
  - 完整的回滚流程

## 使用流程

### 首次部署流程

```bash
# 1. 克隆项目
git clone https://github.com/QAZqweCbc/autoKr.git
cd autoKr

# 2. 给脚本添加执行权限
chmod +x check-environment.sh deploy.sh update.sh rollback.sh

# 3. 检查环境（推荐）
./check-environment.sh

# 4. 执行部署
./deploy.sh

# 5. 访问系统
# 前端: http://localhost:3000
# API: http://localhost:3000/api
```

### 更新流程

```bash
# 1. 进入项目目录
cd /opt/kiro-account-manager

# 2. 执行更新（自动备份）
./update.sh

# 3. 如果更新失败，快速回滚
./rollback.sh
```

### 回滚流程

```bash
# 1. 进入项目目录
cd /opt/kiro-account-manager

# 2. 执行回滚
./rollback.sh

# 3. 查看服务状态
pm2 status
```

## 技术亮点

### 1. 智能依赖更新

```bash
# 只在package.json变化时更新依赖
if git diff HEAD@{1} HEAD --name-only | grep -q "package.json"; then
    npm install
fi
```

### 2. 自动密钥生成

```bash
# 生成32字节的安全密钥
JWT_SECRET=$(node -e "console.log(require('crypto').randomBytes(32).toString('hex'))")
MAIN_API_KEY=$(node -e "console.log(require('crypto').randomBytes(32).toString('hex'))")
```

### 3. 健康检查

```bash
# 检查主服务
if curl -f http://localhost:3000/health &> /dev/null; then
    print_success "主服务运行正常"
else
    print_error "主服务健康检查失败"
    exit 1
fi
```

### 4. 自动备份

```bash
# 备份代码版本
CURRENT_COMMIT=$(git rev-parse HEAD)
echo "$CURRENT_COMMIT" > backups/last_commit.txt

# 备份.env文件
cp .env "backups/backup_$TIMESTAMP.env"

# 备份数据库
mysqldump -u "$MYSQL_USER" -p"$MYSQL_PASSWORD" "$MYSQL_DATABASE" | gzip > "backups/backup_$TIMESTAMP.sql.gz"
```

### 5. 彩色输出

```bash
# 定义颜色
RED='\033[0;31m'
GREEN='\033[0;32m'
YELLOW='\033[1;33m'
BLUE='\033[0;34m'
NC='\033[0m'

# 使用彩色输出
print_success() {
    echo -e "${GREEN}✅ $1${NC}"
}
```
