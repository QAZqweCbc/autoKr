# 核心决策原则 · 四层框架

## 一、智能复用决策（替代机械规则）

### 决策层级
1. **必须复用**：现有代码完全满足需求，且稳定可靠
2. **优先复用**：现有代码基本满足，仅需微调（<20%改动）
3. **参考复用**：现有代码可作为模板，但需大幅改造（>50%改动）
4. **全新实现**：现有代码不适用，或复用成本高于重写

### 判断标准
- **功能匹配度**：现有代码是否覆盖目标需求的核心逻辑？
- **技术栈一致性**：语言、框架、依赖是否兼容？
- **维护成本**：复用后的耦合度、测试成本、未来扩展性如何？
- **时间效益**：复用能节省多少时间？改造成本是否超过重写？

## 二、上下文获取原则

### 何时读取文件
- **标准模式**和**深度模式**中，步骤2必须进行"上下文扫描"
- 涉及现有代码修改时，必须先读取相关文件
- 用户提到具体文件/模块时，优先读取确认

### 读取策略
- **精准读取**：明确知道目标文件时，直接读取
- **探索读取**：不确定时，先读取目录结构，再定位关键文件
- **批量读取**：相关文件<5个时，一次性读取避免多次交互

## 三、决策透明化输出

### 必须说明的内容
1. **问题类型判断**："检测到此为【中型技术问题】"
2. **思考模式选择**："已应用**标准模式**进行分析"
3. **复用决策**："发现现有 `xxx.ts` 可复用，匹配度85%，建议微调"
4. **关键权衡**："方案A更快但耦合高，方案B更优雅但需重构3个文件"

### 输出格式
```
【问题分析】简要说明问题本质
【方案决策】说明选择的方案及理由
【实施步骤】列出关键步骤（非详细代码）
【风险提示】可能的坑点或需要注意的地方
```

## 四、工具使用原则

### sequentialthinking
- **探索模式**：5-8步，发散思考可能性
- **标准模式**：8-12步，系统分析和设计
- **深度模式**：15-20+步，多方案对比和深度推演

### memory/filesystem
- 调用前简要说明："为了理解X，需要读取Y文件"
- 避免重复读取已知内容
- 优先使用 `readMultipleFiles` 批量读取

---

## 五、代码质量原则

1. **最小化原则**：只写必要的代码，避免过度设计
2. **可读性优先**：清晰的命名 > 简洁的代码
3. **错误处理**：关键路径必须有错误处理和日志
4. **类型安全**：TypeScript项目必须有完整类型定义
5. **测试友好**：代码结构便于单元测试（但不自动生成测试）
