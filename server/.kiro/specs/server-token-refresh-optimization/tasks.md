# Server Token 自动刷新优化 - 任务清单

## 阶段一：P0 功能（核心优化）

### 任务 1.1：数据模型扩展
- [x] 1.1.1 扩展 Account 接口，添加错误状态字段
  - `lastError?: string`
  - `lastCheckedAt?: number`
  - `consecutiveFailures?: number`
  - `credentials.expiresAt?: number`
- [x] 1.1.2 更新 MySQL 数据库 schema
  - 添加新字段到 accounts 表
  - 创建数据库迁移脚本
- [x] 1.1.3 更新 JSON 存储适配器
  - 兼容新字段
  - 数据迁移逻辑
- [x] 1.1.4 更新 account-mapper 工具
  - 映射新字段
  - 向后兼容处理

### 任务 1.2：智能过期检测
- [x] 1.2.1 实现 `needsRefresh()` 函数
  - 检查 Token 过期时间
  - 过期前 5 分钟触发刷新
  - 处理无过期时间的情况
- [x] 1.2.2 修改 `performAutoRefresh()` 函数
  - 集成智能过期检测
  - 只刷新需要刷新的账号
  - 记录跳过的账号数量
- [x] 1.2.3 刷新时记录过期时间
  - 从 OIDC 响应中提取 `expires_in`
  - 计算并保存 `expiresAt`
  - 更新数据库

### 任务 1.3：账号状态管理
- [x] 1.3.1 实现 `shouldSkipAccount()` 函数
  - 检测封禁状态
  - 检测连续失败次数
  - 检测 OAuth 凭证完整性
  - 返回跳过原因
- [x] 1.3.2 刷新失败时更新错误状态
  - 记录 `lastError`
  - 更新 `lastCheckedAt`
  - 增加 `consecutiveFailures`
- [x] 1.3.3 刷新成功时重置状态
  - 清除 `lastError`
  - 更新 `lastCheckedAt`
  - 重置 `consecutiveFailures` 为 0
- [x] 1.3.4 添加重置错误状态 API
  - `POST /api/accounts/:id/reset-error`
  - `POST /api/accounts/reset-errors` (批量)

### 任务 1.4：刷新后同步账号信息
- [x] 1.4.1 修改 `refreshAccountToken()` 函数
  - Token 刷新成功后调用 `syncAccountUsage()`
  - 更新使用量信息
  - 更新订阅信息
- [x] 1.4.2 增强封禁检测
  - 检测 423 状态码
  - 检测 `AccountSuspendedException`
  - 标记账号状态为已封禁
- [x] 1.4.3 错误处理优化
  - 同步失败不影响 Token 刷新成功状态
  - 记录详细的同步错误日志
  - 区分 Token 刷新错误和同步错误

## 风险和依赖

### 风险
1. 数据库迁移可能影响现有数据
2. 配置热更新可能导致服务中断
3. 并发刷新可能触发 API 限流

### 缓解措施
1. 提供数据库备份和回滚方案
2. 配置更新前验证有效性
3. 实现批次间延迟和重试机制

### 依赖
1. AWS OIDC API 稳定性
2. Kiro API 可用性
3. 数据库读写性能
