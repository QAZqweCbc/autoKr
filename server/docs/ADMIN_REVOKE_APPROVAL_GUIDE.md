# 管理员释放审批功能使用指南

## 功能概述

管理员后台现已支持审批用户提交的Token释放申请。当用户请求释放Token时，如果释放理由不包含自动审批关键词，申请会进入人工审批队列，等待管理员处理。

## 功能位置

登录管理员后台后，在"用户管理"页面可以看到：

1. **待审批申请** - Token申请审批
2. **待审批的释放申请** - Token释放审批（新增）
3. **用户列表** - 用户管理
4. **Token分配记录** - 分配历史

## 释放申请审批流程

### 1. 查看待审批的释放申请

在"待审批的释放申请"卡片中，可以看到：

| 列名 | 说明 |
|------|------|
| 序号 | 申请序号 |
| 用户名 | 提交申请的用户 |
| 邮箱 | 用户邮箱 |
| 账号 | 要释放的账号邮箱 |
| 释放理由 | 用户提供的释放理由 |
| 申请时间 | 提交时间 |
| 操作 | 批准/拒绝按钮 |

### 2. 批准释放申请

点击"批准释放"按钮：
- 系统会立即释放Token
- 账号状态变为 `active`（可重新分配）
- 用户的Token配额释放
- 申请从待审批列表中移除

### 3. 拒绝释放申请

点击"拒绝"按钮：
- 弹出确认对话框
- 确认后拒绝释放申请
- 申请从待审批列表中移除
- Token保持分配状态

## 自动审批规则

以下情况会**自动审批通过**，不会进入人工审批队列：

### 自动通过的关键词

#### 中文
- 封禁
- 不可用
- 额度已满
- 过期

#### 英文
- banned / ban
- unavailable / not available
- quota / full / limit
- expired / expire

### 示例

✅ **自动通过（不会出现在待审批列表）**:
- "账号被封禁"
- "账号不可用了"
- "额度已满无法使用"
- "Token已过期"

❌ **需要人工审批（会出现在待审批列表）**:
- "换一个新的"
- "不想用了"
- "测试完成"

## 操作说明

### 批准释放

```
1. 查看释放理由，判断是否合理
2. 点击"批准释放"按钮
3. 系统自动处理：
   - 更新分配记录状态为 revoked
   - 释放账号（状态改为 active）
   - 用户配额 +1
4. 显示成功提示
5. 自动刷新列表
```

### 拒绝释放

```
1. 查看释放理由，判断不应释放
2. 点击"拒绝"按钮
3. 确认拒绝操作
4. 系统处理：
   - 清除释放理由
   - 保持Token分配状态
5. 显示成功提示
6. 自动刷新列表
```

## 注意事项

1. **释放理由审查**
   - 仔细阅读用户提供的释放理由
   - 判断理由是否合理
   - 必要时可联系用户确认

2. **账号状态检查**
   - 只有 `active` 状态的Token才能被释放
   - 释放后账号会回到账号池，可重新分配

3. **用户配额管理**
   - 释放Token后，用户的已用配额会减少
   - 用户可以立即申请新的Token

4. **批量操作**
   - 目前不支持批量审批
   - 需要逐个处理释放申请

## 常见场景处理

### 场景1：账号确实被封禁

**用户理由**: "账号被AWS封禁"

**处理**: 
- ✅ 批准释放
- 理由：账号确实不可用，应该释放

### 场景2：用户想换新账号

**用户理由**: "想换个新的账号"

**处理**:
- ❌ 拒绝释放
- 理由：账号正常可用，不应随意释放
- 建议：联系用户说明情况

### 场景3：额度用完

**用户理由**: "额度已满，无法继续使用"

**处理**:
- ✅ 批准释放
- 理由：账号额度已满，应该释放并分配新账号

### 场景4：测试完成

**用户理由**: "测试完成，不再需要"

**处理**:
- 根据实际情况判断
- 如果是临时测试用户：✅ 批准
- 如果是正式用户：❌ 拒绝，建议保留

## API端点

管理员后台使用以下API端点：

```
GET  /api/admin/revoke-requests/pending  - 获取待审批的释放申请
POST /api/admin/revoke-requests/:id/approve - 批准释放申请
POST /api/admin/revoke-requests/:id/reject  - 拒绝释放申请
```

## 数据结构

### 释放申请记录

```typescript
{
  id: string                 // 分配记录ID
  user_id: string           // 用户ID
  username: string          // 用户名
  email: string             // 用户邮箱
  account_email: string     // 账号邮箱
  revoke_reason: string     // 释放理由
  requested_at: number      // 申请时间（时间戳）
  status: 'active'          // 当前状态（只有active的才会出现）
}
```

## 监控和统计

### 查看释放统计

在"Token分配记录"表格中可以看到：
- 状态为 `已释放` 的记录
- 释放时间
- 释放原因（如果有）

### 审批效率

建议：
- 每天至少检查一次待审批列表
- 及时处理释放申请（建议24小时内）
- 对于明显合理的申请，快速批准

## 故障排查

### 问题1：释放申请不显示

**可能原因**:
- 申请已被自动审批通过
- 申请的Token状态不是 `active`

**解决方法**:
- 检查"Token分配记录"中的状态
- 查看后端日志确认自动审批结果

### 问题2：批准后账号未释放

**可能原因**:
- 网络请求失败
- 后端处理异常

**解决方法**:
- 刷新页面重试
- 查看浏览器控制台错误
- 检查后端日志

### 问题3：待审批列表不更新

**可能原因**:
- 页面未刷新
- WebSocket连接断开

**解决方法**:
- 点击"刷新"按钮
- 刷新整个页面
- 检查网络连接

## 最佳实践

1. **及时处理**
   - 定期检查待审批列表
   - 避免积压过多申请

2. **合理判断**
   - 仔细阅读释放理由
   - 必要时联系用户确认

3. **记录备注**
   - 对于特殊情况，可在内部系统记录
   - 便于后续追溯

4. **用户沟通**
   - 拒绝申请时，建议通过其他渠道告知用户原因
   - 帮助用户理解释放规则
