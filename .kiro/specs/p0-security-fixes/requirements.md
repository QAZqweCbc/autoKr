# P0 安全修复 - 需求文档

## 项目概述

**项目名称**: P0级安全问题修复  
**优先级**: 🔴 P0 - 紧急  
**预计工期**: 1-2天  
**目标**: 修复后端代码中最严重的安全问题和稳定性问题

## 背景

根据代码审核报告，发现以下严重问题：
1. 数据库初始化时序问题导致服务启动失败
2. 默认加密密钥暴露，存在严重安全隐患
3. CORS配置过于宽松，允许任何来源访问
4. 缺少认证中间件，API端点无保护

这些问题必须立即修复，否则系统存在严重的安全风险和稳定性问题。

## 用户故事

### US-1: 数据库初始化稳定性
**作为** 系统管理员  
**我希望** 服务启动时数据库初始化过程稳定可靠  
**以便** 避免"MySQL 未初始化"错误，确保服务正常运行

**验收标准**:
- [ ] 服务启动时不再出现"MySQL 未初始化"错误
- [ ] 数据库初始化失败时能够优雅降级到JSON存储
- [ ] 所有依赖数据库的服务都能正确检查初始化状态
- [ ] 启动日志清晰显示数据库初始化状态
- [ ] 前端调用API时不会因为数据库未初始化而返回500错误

**优先级**: P0 - 最高

---

### US-2: 强制加密密钥配置
**作为** 安全管理员  
**我希望** 系统强制要求配置加密密钥  
**以便** 确保所有敏感数据使用唯一的密钥加密，防止数据泄露

**验收标准**:
- [ ] 启动时检查 `ENCRYPTION_KEY` 环境变量是否存在
- [ ] 如果未设置加密密钥，服务拒绝启动并显示清晰的错误提示
- [ ] 加密密钥长度必须至少32字符
- [ ] 提供密钥生成命令示例（如 `openssl rand -base64 32`）
- [ ] `.env.example` 文件包含加密密钥配置说明
- [ ] 启动日志显示"✅ 加密密钥已配置"确认信息

**优先级**: P0 - 最高

---

### US-3: CORS安全配置
**作为** 安全管理员  
**我希望** 系统只允许授权的来源访问API  
**以便** 防止CSRF攻击和未授权访问

**验收标准**:
- [ ] 移除 `origin: '*'` 配置
- [ ] 通过环境变量 `ALLOWED_ORIGINS` 配置允许的来源
- [ ] 默认只允许 `localhost` 和配置的域名
- [ ] WebSocket连接也应用相同的CORS策略
- [ ] 支持多个允许的来源（逗号分隔）
- [ ] 未授权的来源访问时返回明确的CORS错误
- [ ] 开发环境和生产环境可以使用不同的CORS配置

**优先级**: P0 - 最高

---

### US-4: API认证保护
**作为** 系统管理员  
**我希望** 所有敏感API端点都需要认证  
**以便** 防止未授权访问和数据泄露

**验收标准**:
- [ ] 创建 JWT 认证中间件
- [ ] 创建管理员权限检查中间件
- [ ] 所有账号管理API需要认证
- [ ] 删除、导出等敏感操作需要管理员权限
- [ ] 未认证请求返回 401 状态码和清晰的错误信息
- [ ] 无权限请求返回 403 状态码和清晰的错误信息
- [ ] 健康检查端点保持公开访问
- [ ] 认证令牌使用环境变量 `JWT_SECRET` 签名

**优先级**: P0 - 最高

---

### US-5: 环境变量验证
**作为** 系统管理员  
**我希望** 启动时验证所有必需的环境变量  
**以便** 及早发现配置问题，避免运行时错误

**验收标准**:
- [ ] 启动时验证所有必需的环境变量
- [ ] 缺少必需变量时拒绝启动并显示清晰的错误信息
- [ ] 验证环境变量的类型和格式（如端口号必须是数字）
- [ ] 提供 `.env.example` 文件作为配置模板
- [ ] 启动日志显示已加载的环境变量（敏感信息脱敏）
- [ ] 支持开发、测试、生产环境的不同配置

**优先级**: P0 - 最高

---

## 功能需求

### FR-1: 数据库初始化状态管理

**描述**: 实现数据库初始化状态跟踪和检查机制

**详细需求**:
1. 添加全局初始化状态标志
2. 所有数据库操作前检查初始化状态
3. 未初始化时返回友好的错误信息或降级到JSON存储
4. 提供 `isDatabaseInitialized()` 辅助函数
5. 提供 `waitForDatabaseInit()` 异步等待函数

**影响范围**:
- `src/services/database.adapter.ts`
- `src/services/mysql.service.ts`
- `src/services/email-config.service.ts`
- `src/services/email-config-manager.service.ts`
- 所有其他依赖数据库的服务

---

### FR-2: 加密密钥验证

**描述**: 启动时强制验证加密密钥配置

**详细需求**:
1. 创建 `validateEncryptionSetup()` 函数
2. 检查 `ENCRYPTION_KEY` 环境变量是否存在
3. 验证密钥长度（至少32字符）
4. 验证失败时显示详细的错误信息和解决方案
5. 在 `src/index.ts` 和 `src/auth-service/index.ts` 启动时调用

**影响范围**:
- `src/utils/crypto.util.ts`
- `src/index.ts`
- `src/auth-service/index.ts`
- `.env.example`

---

### FR-3: CORS配置增强

**描述**: 实现基于环境变量的CORS白名单配置

**详细需求**:
1. 从 `ALLOWED_ORIGINS` 环境变量读取允许的来源
2. 支持多个来源（逗号分隔）
3. 开发环境默认允许 `localhost` 的所有端口
4. 生产环境必须明确配置允许的来源
5. WebSocket 和 HTTP 使用相同的 CORS 策略
6. 提供清晰的 CORS 错误信息

**影响范围**:
- `src/index.ts`
- `src/auth-service/index.ts`
- `.env.example`

---

### FR-4: JWT认证中间件

**描述**: 实现基于JWT的认证和授权中间件

**详细需求**:
1. 创建 `requireAuth` 中间件验证JWT令牌
2. 创建 `requireAdmin` 中间件验证管理员权限
3. 从 `Authorization: Bearer <token>` 头部提取令牌
4. 使用 `JWT_SECRET` 环境变量验证令牌
5. 将解码后的用户信息附加到 `req.user`
6. 提供清晰的认证错误信息（401/403）

**影响范围**:
- 新建 `src/middleware/auth.middleware.ts`
- `src/routes/account.routes.ts`
- `src/routes/admin.routes.ts`
- `src/routes/config.routes.ts`
- `src/routes/token.routes.ts`
- 所有需要保护的路由

---

### FR-5: 环境变量验证器

**描述**: 创建统一的环境变量验证机制

**详细需求**:
1. 创建环境变量验证器（使用 zod 或类似库）
2. 定义所有必需和可选的环境变量
3. 验证类型、格式、范围
4. 提供默认值（仅限非敏感配置）
5. 验证失败时显示详细的错误信息
6. 在服务启动最开始调用

**影响范围**:
- 新建 `src/utils/env-validator.ts`
- `src/index.ts`
- `src/auth-service/index.ts`
- `.env.example`

## 非功能需求

### NFR-1: 性能
- 环境变量验证应在 100ms 内完成
- 认证中间件不应增加超过 10ms 的请求延迟
- 数据库初始化检查应使用缓存，避免重复检查

### NFR-2: 安全性
- 所有敏感信息（密钥、密码）不得出现在日志中
- JWT令牌使用 HS256 算法签名
- 加密密钥长度至少 256 位
- CORS配置遵循最小权限原则

### NFR-3: 可维护性
- 所有新增代码必须包含 TypeScript 类型定义
- 关键函数必须包含 JSDoc 注释
- 错误信息必须清晰、可操作
- 配置示例必须完整、准确

### NFR-4: 兼容性
- 不破坏现有API接口
- 向后兼容现有的配置文件
- 支持 Node.js 18+ 版本

---

## 技术约束

1. **技术栈**: Node.js + TypeScript + Express
2. **认证方式**: JWT (jsonwebtoken 库)
3. **环境变量**: dotenv 库
4. **验证库**: zod 或 joi
5. **不引入新的重大依赖**: 优先使用已有依赖

## 风险和缓解措施

### 风险1: 现有客户端无法访问API
**影响**: 高  
**概率**: 中  
**缓解措施**:
- 提供过渡期，同时支持认证和非认证访问
- 提供清晰的迁移指南
- 在响应头中提示需要认证

### 风险2: 环境变量配置错误导致服务无法启动
**影响**: 高  
**概率**: 中  
**缓解措施**:
- 提供详细的错误信息和解决方案
- 提供完整的 `.env.example` 文件
- 在文档中提供配置检查清单

### 风险3: CORS配置过于严格导致合法请求被拒绝
**影响**: 中  
**概率**: 低  
**缓解措施**:
- 开发环境使用宽松的配置
- 提供 CORS 调试日志
- 在文档中说明如何添加允许的来源

### 风险4: JWT密钥泄露
**影响**: 高  
**概率**: 低  
**缓解措施**:
- 强制使用环境变量，不允许硬编码
- 在文档中强调密钥安全的重要性
- 提供密钥轮换指南
